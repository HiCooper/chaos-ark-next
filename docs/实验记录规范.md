# 实验记录规范（experiments.json）

## 一、为什么要立这个规矩

`web/public/data/experiments.json` 是**手工维护**的实验登记簿（引擎不产出它）。
2026-09-24 出过一次事故：3 条记录缺 `hypothesis/params/results/goals`，前端展开时抛错、
**整页白屏**。根因不是那 3 条记录，而是**没有 schema、没有校验、没有生成器**——字段漂移迟早发生。

现在的规矩：**schema 唯一（`engine/lab_registry.py`）→ 生成器产骨架 → 校验器把关 → 管线拒绝放行**。

## 二、两类记录

| kind | 用途 | 必填字段 |
|---|---|---|
| `experiment` | 对照实验（有基准与变体对比） | `vs` `hypothesis` `params` `results` `goals` `robustness` |
| `change` | 口径变更登记（不做对照、只记变更） | `vs` `why` `result` |

公共必填：`id` `date` `kind` `title` `layer` `status` `conclusion`；
建议字段：`artifacts`（可复现产物，校验会检查文件是否存在；`cache/` 与通配路径不检查）、`caveat`（一条告警）、
`next`（后续动作）、`date_note`（日期只精确到月时的说明）。

## 三、字段细则

- **`id`**：小写 kebab-case（允许点号，如 `baseline-1.6.0`），全局唯一。
- **`date`**：`YYYY-MM-DD`，早期记录可 `YYYY-MM`（配 `date_note` 说明）。
- **`status`**：只能取 7 个徽章之一 ——
  `已采用` `已落参` `验证通过`（绿）· `已否决`（红）· `部分否决` `待拍板`（黄）· `已记录`（灰）。
  **徽章只放这四个字**：长说明一律进 `conclusion` 或 `caveat`（校验会拒绝含『｜』或超过 6 字的 status）。
- **`title`** ≤ 90 字、**`layer`** ≤ 40 字：卡片头一行放得下。
- **`results` 行**两种合法形态，**不接受空行**：
  - 数值型：`{label, cagr, maxdd, sharpe?, note?}`（`cagr`/`maxdd` 必须是数字）；
  - 文字型：`{label, note}`（分布/定性结论，例如「最差 5 个起点」「逐年短板」）。
- **`params` 行**：`{k, v, note?}`，`k` 与 `v` 非空。
- **`goals`**：`{annualized, drawdown}` 两段话（分别回答年化与回撤）。
- **`conclusion`**：必须有；若落参要写清 `ENGINE_VERSION` 与代价披露。
- **禁止 `TODO`**：生成器会用 `TODO` 占位，**未填完校验必然失败**——这是刻意的。

## 四、怎么产出（三条命令）

```bash
# 1) 生成字段齐全的骨架（自动插到最前面）
python3 engine/lab_registry.py new <id> --kind experiment --title "…" --layer "信号层（打分）"
python3 engine/lab_registry.py new <id> --kind change     --title "…" --layer "结算层（记账口径）"

# 2) 填完字段后自检（有问题非零退出，并逐条指出哪个字段怎么不对）
python3 engine/lab_registry.py check

# 3) 一次性迁移：给历史条目补 kind
python3 engine/lab_registry.py backfill-kind
```

## 五、在哪里被强制

| 环节 | 行为 |
|---|---|
| `python3 engine/ark.py verify` | 新增「实验登记簿 schema 校验」，失败即整体验收失败 |
| `python3 engine/ark.py daily` | 同步/发布站点**之前**校验，坏记录直接中止发布 |
| 前端 `Lab.tsx` | 每条记录一个 `CardBoundary`：万一有脏数据只显示一张「数据异常」卡，绝不白屏 |
