# 数据兜底：申万官方日线滞后时，用实时行情补尾部

## 一、问题

结论层（今日研判 / 我的持仓）的信号全部来自**申万行业指数**（`cache/panel.json` 是
`feature_store` 的唯一输入）；而申万**官方日线**接口 `akshare.index_hist_sw` 有发布滞后：

```
2026-09-23 22:00 实测
  index_hist_sw            最后一天 2026-09-21   ← 官方日线
  index_analysis_daily_sw  最后一天 2026-09-21   ← 官方日指标
  index_realtime_sw        知道 09-22 收盘 + 09-23 当前会话（实时）
  fund_etf_hist_sina       最后一天 2026-09-23   ← ETF（结算层）更新及时
  stock_zh_index_daily     最后一天 2026-09-23   ← 基准（新浪）
```

后果：ETF 侧（算钱的）已经到 09-23，但**结论层停在 09-21**，复盘、买卖清单、影子账户
全都推进不了——不是缺价格，是缺"买什么"的清单。

## 二、兜底规则（`datasource_sw.fill_realtime_tail`）

只在「官方最后一天 < 基准（新浪）最后一天，且缺口 ≤ 2 天」时启用：

| 字段 | 来源 | 是否估算 |
|---|---|---|
| 收盘价（当前会话那天的完整 bar） | `index_realtime_sw` 最新价 | **否**（实时真值；盘中抓取时标注 intraday） |
| 收盘价（更早那一天） | `index_realtime_sw` 昨收盘 | **否**（实时真值） |
| 开/高/低（更早那一天） | 无 → 置为收盘价 | 是 |
| **成交量 / 成交额** | 上一官方日 × 沪深300 成交量环比 | **是** |
| 实时缺失的个别指数（如已停更的 801961） | 当日全体中位涨跌幅推算 | 是 |

为什么量额一律估算：实测实时接口的成交量/成交额与官方日线**量纲不同**
（801010：官方 09-21 量 36.2/额 299.6，实时 2938.9/24318.7，同比例偏大约 81 倍），
直接取用会制造 ~80 倍的假放量。基准量比只用量（`bench/<mc>.json` 的 volume），是比值，量纲无关。

**对齐体检**（防止把两天错位对齐）：补完后比较「全体行业指数在该窗口的中位涨跌」与
「沪深300 同窗口涨跌」，偏差 > 5pp 就放弃兜底并打日志。实测 2026-09-22→23：
行业中位 −0.53% vs 基准 −0.49% ✓。

## 三、可追溯与自动修复

- 每条兜底记录都带 `src`（`realtime` / `realtime_prev_close` / `realtime_xs_median`）
  与 `est`（被估算或来源非官方的字段清单）；官方行两者都没有。
- L0 写入带 `overwrite_est=True`（`rawstore.put`）：**官方值可以覆盖带 `est` 的估算行**，
  而一手数据彼此之间仍然先到先得、绝不互相覆盖（`_selftest` 已固化该语义）。
  于是官方出数后，只要重跑 `ark.py daily`，估算行会被真值替换、结论自动重算。
- `ark.py status` 会在水位报告里显式列出「含实时兜底日」；
  管线把标记写进 `today.json` 与受影响日期的 `day/<date>.json`（字段 `realtime_fill`），
  「今日研判」与「我的持仓」页顶部显示黄色提示条。

## 四、边界（明确不做的事）

- 缺口 > 2 天：只有一天的「昨收」可用，更早的日子补不了 → 直接放弃兜底，等官方。
- 不用东财 BK 板块兜底：本机代理直接 `ProxyError`，且当年正是因为它被限流 + 口径不权威
  才换到申万官方。
- 不用 ETF 价格重做信号层：ETF 中位上市日 2020-12-29（2018-01-02 前只有 36/123），
  且没有申万 L1/L2/L3 层级结构 → 会把回测缩到 2022 之后并丢掉共振逻辑（详见
  `docs/口径变更-2026-09-23-可执行账户.md` 第十一节）。

## 五、日常命令

```bash
python3 engine/ark.py daily     # 官方出数前：自动兜底，结论推进到当天
python3 engine/ark.py status    # 看「含实时兜底日」提示
python3 engine/ark.py verify    # L0 sha256 + 账本重放 + 特征指纹
```

## 六、兜底代价的实测（2026-09-24 官方出数后回看）

2026-09-23 晚用实时行情兜底了 09-22/09-23 两天；09-24 上午申万官方出数，正好可以**逐条比对估算与真值**
（119 个指数 × 2 天，抽 10 个指数做明细）：

| 字段 | 来源 | 中位误差 | 平均 | 最坏 |
|---|---|---|---|---|
| 收盘价（09-22 用实时"昨收"） | 实时真值 | **0.000%** | 0.000% | 0.000% |
| 收盘价（09-23 用实时"最新价"，21:45 抓取） | 实时真值 | 0.001% | 0.02% | 0.09% |
| 成交量 | 估算（上一官方日 × 沪深300量比） | 4.75% | 7.37% | 35.9% |
| 成交额 | 同上 | 5.90% | 9.19% | 37.1% |

对决策的影响：`vol_ratio` / `amount_ratio` 都是「5 日均值 ÷ 20 日均值」，单日误差 δ 对该比值的影响
≈ 0.15δ（新的一天在分子里占 1/5、在分母里占 1/20）→ 中位 ~0.9%、最坏 ~5.5%；
量能类维度在综合分里的权重合计约 22%（`exhaust` 12% + `risk` 一部分），因此综合分偏移中位 <0.3 分、
最坏 ~1 分（满分 100）。

**估算版 vs 官方版的实际结论差异（09-23）**：

| 项目 | 估算版 | 官方版 |
|---|---|---|
| 当日结论 | 半导体设备 · 埋伏 | 半导体设备 · 埋伏（**相同**） |
| 综合分 | 68.78 | 68.10（−0.68） |
| 环境 | 中性（热度 52） | 中性（热度 53） |
| 结算口径年化 / 回撤 / Sharpe | 11.84% / −33.01% / 0.685 | 完全一致 |
| 成交笔数 / 平均投出 | 334 / 46.5% | 完全一致 |

自动修复同时验证通过：官方值覆盖了估算行（manifest `replaced_est: 2`，行内 `est` 标记消失），
`panel.realtime_fill` 变为 `null`，页面顶部的"含实时兜底日"提示条自动消失。

**因此"只能兜底、不能当主源"的准确含义是三条能力边界，而不是"数据不可靠"**：

1. 它只是**快照**：只有「昨收 + 当日 bar」，最多补 2 天；覆盖 119/120 个行业指数（已停更的 801961 缺失），
   且不含基准指数（基准走新浪，本来就及时）。
2. **量额量纲未标定**：同一指数两个接口的量额系统差一个固定倍数（实测 ~25–85×，随时点变化，
   可判定为约 100× 的单位差异，但没有重叠交易日可严格标定；连官方两个接口之间也不自洽——
   `index_analysis_daily_sw` 的「均价×成交量」对不上 `index_hist_sw` 的「成交额」）。
3. **盘中不是收盘**：最新价与量额都是盘中累计值，必须 15:05 之后抓取；跨节假日/停市还要靠
   对齐体检（行业中位涨跌 vs 沪深300 同窗口，偏差 >5pp 直接放弃）挡住"这根 bar 属于哪一天"的风险。
