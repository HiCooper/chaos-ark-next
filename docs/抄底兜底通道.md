# 抄底兜底通道（DIP）：空窗日超跌回升补位

日期：2026-10-29　　状态：**已落参启用**（`config.DIP.enabled = True`，`ARK_DIP=0` 可临时关闭做对照）
涉及：`engine/dip.py`（候选生成）、`engine/review.py`（并入候选池）、`engine/config.py:DIP`、
`web/src/{MyBook,Review,Today}.tsx`（页面标注）、`engine/lab_dip.py`、`engine/lab_dip_wf.py`（实验）

## 一、为什么会有这个东西

主策略在恐慌期会**连续零结论、资金闲置**：10-19 至 10-28 连续 5~11 个交易日 0 结论，
账户均投出只有 51%。问的是：**这时候要不要用「超跌 + 止跌回升」的板块补位？**

先做了纯统计（申万 120 个 L1/L2 序列，2018 起，超额相对沪深300，未来 20 日）：

| 条件 | 事件数 | 超额胜率 | 超额均值 | 最差 |
|---|---|---|---|---|
| 全样本 | — | 49.0% | +0.24% | −67.7% |
| 20 日跌幅 ≤ −15% | 14862（去重叠 2355） | 64.7%（56.6%） | +3.08%（+1.60%） | −35.0% |
| 同上 **且较近 5 日低点回升 > 3%** | 4418（去重叠 1316） | **72.8%（69.8%）** | **+4.64%（+4.10%）** | **−20.9%** |

两件事同时成立才有效：**跌得深（一阶导）+ 跌不动了（二阶导）**。只满足前半段时胜率 61%、最差 −35%。

## 二、落地方式决定成败（这条最值钱）

同一个信号，三种接法，结果完全不同：

| 接法 | 年化 | 回撤 | Calmar | 关键指标 |
|---|---|---|---|---|
| 基线（无 DIP） | 13.87% | −33.13% | 0.419 | 均投出 51.3% |
| **A. 独立 20% 专用额度** | **11.96%（−1.91pp）** | −30.83% | 0.388 | sleeve 平均敞口仅 **6.4%** |
| B. 无条件并入候选池 | 14.49% | −28.39% | 0.510 | 样本内 −2.11pp / 样本外 +2.98pp |
| **C. 仅空窗日补位（采用）** | **15.56%（+1.69pp）** | **−27.64%** | **0.563** | 样本内 −1.06pp / 样本外 +2.87pp |

A 的失败点很具体：信号聚集在熊市（2022 年 35 笔、2024 年 32 笔），牛市几乎不触发（2019 年 3 笔），
**专用额度常年闲置**——20% 的资金平均只用出 6.4%，牛市那 20% 的机会成本直接吃掉全部 edge。
这是本项目反复验证过的规律：有限资金、只买不卖的账户里，任何「预留资金」的设计都赔年化。

B 的问题在**稀释**：DIP 单笔均值 +2.94%，只有主策略（+13.46%）的 22%，却占了 24% 的建仓笔数，
且 71% 落在主策略也用过的标的上——不是新 alpha 源，是「用高价值槽位换低价值交易」。
牛市里净损失（样本内 −2.11pp），熊市里因为主策略本来就闲着，才是补充。

C 因此加了一条件：**只在主策略当日零候选时补位**。牛市伤害减半（−1.06pp），熊市收益基本保留（+2.87pp）。
附带发现：461 条空窗日信号 **100% 落在 PANIC/DEFEND**（435 + 26），所以**不需要再叠 regime 闸门**——
「主策略零候选」和「极端环境」在数据里是同一件事。

## 三、生产实现（已启用）

```python
# engine/config.py
DIP = {
    "enabled": os.environ.get("ARK_DIP", "0") == "1",   # 默认关闭
    "dd_window": 20, "dd_trigger": -0.15,               # 20 日跌幅 ≤ -15%
    "reb_window": 5,  "reb_trigger": 0.03,              # 较 5 日低点回升 > 3%
    "hold_days": 20,                                    # 持有 20 个交易日
    "composite": 45.0,                                  # 候选分：轻仓 + 排序靠后
    "only_blank_days": True,                            # 只在空窗日补位
}
```

- `engine/dip.py:build_candidates()` 产出与生产候选**同构**的 dict（`action='DIP'`），
  校验「T+1 有开盘价才发信号」，同一天同一 ETF 只留一条；
- `engine/review.py` 在 `trades_exec` 之后并入，**只影响结算与 `sim.json`，不进 `today.json` 的结论**；
- 因此前端「今日研判」的结论数、环境分、日历完全不受影响；受影响的是**账本**（成交数与净值）。

**开关**：`config.DIP["enabled"]`（2026-10-29 落参，默认 True）；`ARK_DIP=0` 可临时关闭做对照。
落参后的生产数字：年化 **15.56%**、回撤 **−27.64%**、Sharpe 0.773、Calmar **0.563**、
均投出 55.0%、成交 455（DIP 建仓 108 笔 / 已结算 106 笔）。结论层不受影响（today.json 仍 0 条）。

**同标冷却已否决**：把同一 ETF 的重复触发按 20 日冷却后，候选 302→84（−72%）、
年化 15.56%→14.33%（−1.23pp）、Calmar 0.563→0.457、样本外 +1.13%→−0.72%。
原因是「多个行业同时超跌」本身就是更强的信号（产业链被整体错杀），分批建仓是特征不是缺陷；
集中度实测上限也只有 5 笔/标的（占 32 槽位的 16%）。故 `same_sid_cooldown = 0`。

## 四、页面标注（必须做，否则用户会误读）

`DIP` 不是结论驱动的，页面上必须一眼可辨：

- 动作列显示 **「抄底」**（黄色 warn 色调），悬浮说明「非结论驱动：主策略当日零候选 + 该行业 20 日跌幅≥15% 且已止跌回升」；
- 「当前持仓」标题旁追加 **「含抄底兜底 N 笔（非结论驱动）」**；
- 今日研判页不出现「抄底」字样（结论未受影响）。

## 五、稳健性（`engine/lab_dip_wf.py`）

| 扫描 | 结果 |
|---|---|
| 跌幅阈值 −10 / −12 / **−15** / −20 | 12.85 / 13.63 / **14.87** / 14.65 |
| 回升阈值 1% / **3%** / 5% | 13.94 / **14.87** / 14.69 |
| 候选分 30 / 40 / **45** / 52 | 14.72 / 14.87 / **14.95** / 14.94 |
| 持有期 10 / **20** / 40 | 15.15 / 14.49 / 13.94 |
| 训练段最优 → 检验段 | (−20%/5%) +1.05pp；**预设(−15%/3%) +2.98pp** |

参数是**平台不是尖峰**；且训练段挑出的「最优」在检验段反而不如预设值——
说明这套阈值是先验定的，不是从组合业绩上拧出来的。

## 六、诚实结论：它不是全天候 alpha

- **样本内（2019-06~2022-12，单边牛市）仍 −1.06pp**：即便只在空窗日补位，DIP 仓位也会占用
  20 个交易日的现金，阻断后续主策略的高价值建仓；
- 收益高度依赖**环境类型**：2023-2026 这种震荡下行 +2.87pp，2020-2021 那种趋势市为负；
- 所以定位是「**恐慌空窗期的参与度补充器**」，不是提高单笔质量的 alpha 源。

**待观察指标**（若日后考虑启用）：连续空窗日的天数、DIP 建仓占比是否超过 25%、
以及「DIP 持仓期间主策略因缺钱被挡下的候选数」——最后这个最能说明它是不是在抢槽位。
